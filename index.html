Rules and Expectations

  1. No unauthorized security testing.

    Do not perform penetration testing, vulnerability scanning, or any other form of security testing without explicit permission from the Dev Corps heads or the Community Steering Heads. Unauthorized testing puts systems, members, and institutional resources at risk.

  2. Repository code licensing.

    By default, all public repositories of the BIC AI Horizon Community are licensed under the BIC AI Horizon Community License, unless a repository states otherwise. The license keeps the work protected, requires proper attribution, and defines how the code may be reused.

  3. Credit all contributors.

    Give explicit credit to every contributor and author whose work you use, adapt, or build upon. Attribution respects their effort and keeps intellectual contributions visible.

  4. Responsible technology use.

    Practice responsible technology use, uphold academic integrity, and respect collaboration boundaries. Ethical behavior keeps learning and development activities safe and trustworthy for everyone.

  5. Positive impact and meaningful contribution.

    Aim to build projects that create positive impact, encourage learning, and contribute meaningfully to the wider community. The goal is to help people and support collective growth.

  6. Preserve repository history.

    Repository history must not be deleted or rewritten. Existing repositories may only be modified by adding new commits and changes; the commit history itself must remain intact.

  7. No history-erasing re-uploads.

    Do not clone a community repository, delete its Git history, and push it back as a fresh repository. Doing so erases authorship records, attribution, and the project's audit trail.

  8. No repository deletion without approval.

    Deleting a repository, including its history, is not allowed without proper review and approval from community members and the Community Steering Heads.

License Notice

By default, all public code across the BIC AI Horizon Community's public repositories is released under the BIC AI Horizon Community License. Reuse, modification, and distribution are permitted in line with the community's rules and attribution requirements.

Examples of Proper and Improper License Use

The examples below show how the license should — and should not — be applied in practice.

Proper use

  • A member reuses a file from a community repository, keeps the original attribution notice intact, credits the source repository in their documentation, and uses the code in line with the community license and rules.
  • A contributor builds on an existing project, clearly marks their own changes, credits the original authors, and states that the resulting work follows the BIC AI Horizon Community License.

Improper use

  • Copying repository code without mentioning the source, removing copyright or attribution notices, or presenting the work as if it were originally your own.
  • Distributing repository code publicly without meeting the license conditions, without giving credit, or using it for unauthorized testing or unethical activities.

Suggested attribution notice

When you reuse or adapt code from a community repository, a notice like the one below keeps the credit and license clear: 

Based on code from <repository name> (BIC AI Horizon Community).
Original author(s): <names>
Source: <repository URL>
License: BIC AI Horizon Community License

Modified by <name> in <month year>.
